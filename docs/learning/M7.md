# M7: Docs and demo

## What we built and why
- `README.md` (sections in spec order), `docs/ARCHITECTURE.md` (Mermaid: loop sequence, sandbox boundary, data flow), `docs/MCP.md`, `CLAUDE.md`, and these notes.

## Key concepts
- **Numbers only from `results/`**: the README marks unmeasured rows as targets. `docs/EVAL_REPORT.md` is overwritten by `patchloop report --all`.

## Interview questions
1. **Walk me through your agent in two minutes.** Task + issue go to a loop that calls Claude with six tools; tools run in a locked-down container; observations are truncated and appended; budgets, retries, loop detection and compaction guard the failure modes; the diff is graded in a fresh container against hidden tests; everything is logged as JSONL and summarised with intervals.
2. **What would you build next?** Real-bug tasks (from repo history), best-of-k with test-based selection (E3), a per-task paired comparison in the report, and a microVM sandbox.
3. **What was the hardest bug while building it?** The PID-limit test starving the shared container. It looked like flaky timeouts and git failures, but the root cause was orphaned processes. The fix was isolation per test and `--init`.

## Break-it exercise
Run `patchloop report --all` with no `results/E*` directories.
**Expected:** the generated `EVAL_REPORT.md` has an empty summary table. **Diagnose:** the report only reads `E*` runs by design, so `oracle` and `smoke` never appear in the headline results.
