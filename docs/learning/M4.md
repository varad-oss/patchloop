# M4: Runner, grader, metrics, report, viewer

## What we built and why
- `evals/runner.py`: parallel (thread pool, default 4) and resumable (an episode file's existence means done). It writes `results/<run>/episodes/*.json` and `trajectories/*.jsonl`. Includes `oracle` and `fake` (give-up) models for free end-to-end checks.
- `evals/grader.py`: a fresh container with the bug applied, then `git apply` of the agent's diff, then the full suite, then F2P/P2P. Diffs that touch tests or test config are rejected outright.
- `evals/metrics.py`: Wilson interval, unbiased pass@k and pass^k, aggregates by difficulty, failure classification.
- `evals/report.py` and `evals/viewer/render.py`: Markdown + SVG from `results/` only, and one static HTML page per run.
- `cli.py`: the **pilot gate**. A paid model refuses to run without `--pilot` (3 tasks, prints measured and extrapolated cost) or `--yes`.

## Key concepts
- **Grade in a fresh container**: the agent's container might have been left in any state (background processes, modified files outside git). Only the diff crosses over.
- **Wilson vs normal interval**: at n=36 and rates near 0 or 1, the normal approximation gives impossible bounds (below 0, above 1). Wilson stays in [0,1] and has better coverage.
- **pass@k** = P(at least 1 of k succeeds) = `1 - C(n-c,k)/C(n,k)`; **pass^k** = P(all k succeed) = `C(c,k)/C(n,k)`. pass@k measures capability with retries; pass^k measures reliability.
- **Failure taxonomy** (`classify_failure`): infrastructure, tamper, budget, tool misuse, never found the bug, broke other tests, wrong fix, checked in that priority order.

## Interview questions
1. **Your agent went from 40% to 47% on 36 tasks. Is that an improvement?** Not demonstrably. The 95% Wilson interval at 40% with n=36 is about 26-56%, so a 7-point move is well inside the noise. You'd need more tasks, several trials per task, or a paired test on the same tasks.
2. **Why is the naive pass@k estimate biased, and what's the fix?** Taking 1 − (1−p̂)^k from a single per-task success rate is biased because p̂ is itself noisy (Jensen's inequality). The unbiased estimator draws k from n samples without replacement: `1 − C(n−c,k)/C(n,k)`, averaged over tasks.
3. **How do you make a long eval run safe to interrupt?** Make it idempotent per unit of work: each episode writes one file at the end, the runner skips existing files, and cost is recorded per episode, so resuming never double-spends and never loses finished work.
